## The rules moved into the database (not left to app discipline)
Constraint migration + tests prove all 7 bite:
1. `rubric_level BETWEEN 1 AND 4` (framework scoring model) — on level descriptions and scores
2. committee `seat_number BETWEEN 1 AND 3` (ว9: 3-member committee)
3. `workload_gate` indicator can never be `is_scored=true` (ภาระงาน is a gate, not a score)
4. membership scope must match the id set (tenancy integrity)
5. one **active** mapping per (evidence, indicator, cycle) via partial unique index `NULLS NOT DISTINCT` — revoked rows free the slot
6. `passed_individual_threshold` is a **GENERATED** column (`total_percent >= 70`) — app cannot write it, so the ≥70%-each rule can't drift
7. `audit_event` UPDATE/DELETE blocked by trigger (append-only survives even a shared DB role — ADR-0005 on-prem reality)

Plus: PA cycle uniqueness (partial index, DPA may repeat), date ordering, email-lowercase, confirmed-mapping-needs-actor, percent ranges.

## CI gates armed by this task
- **migration-validation** — upgraded from `prisma validate` stub to: spin up a Postgres service → `migrate deploy` (proves up-path) → run constraint tests. Now a real gate.
- Note: no `migrate diff` drift check — the constraints migration adds generated columns/CHECKs/triggers/partial indexes Prisma's schema can't represent, so diff would always report a difference. The constraint tests are the stronger check.

## Known limitations / carried
1. **Down-migrations**: Prisma is forward-only; `migrate reset` is the teardown path but Prisma blocks it under Claude Code, so it was proven via `DROP SCHEMA` + `migrate deploy` instead. On-prem rollback strategy = restore-from-backup, not down-migrations — must be covered by the backup/restore release gate.
2. **No seed yet**: the ว9/ว10 taxonomy rows (15+15 indicators, level descriptions, weights) are not seeded — that's a focused follow-up (`SEIP-DB-002` seed) so the values get their own review against the PDF. Schema is proven to *accept* them by the constraint tests.
3. **`prisma generate`** (client) not run/committed — belongs with the first API code (SEIP-API-001) that consumes it.
4. Tenant isolation is *enforceable* (school_id everywhere, CHECKs) but the repository layer that guarantees it by construction (SEC-TEN-1) is API work, not schema.
