### 0.3 วิธีอ่านเอกสารนี้

- **ลำดับความสำคัญ (Priority)**: **Must** = ขาดไม่ได้สำหรับการเปิดใช้ v1 กับ สพท. นำร่อง; **Should** = เป้าหมายของ v1 อาจเลื่อนไป v1.x ได้โดยมีเหตุผล; **Could** = ทำถ้ามีเวลา; **v2** = เลื่อนออกไปโดยเจตนา (ส่วนใหญ่ตาม D3).
- **Platform**: Mobile (Flutter), Web, Backend. ข้อที่ระบุหลาย platform ต้องผ่านเกณฑ์ทุก platform ที่ระบุ.
- **สถานะเทียบกับ baseline** (`origin/feat/cleanup-L2-e2e-depth`): **มีแล้ว** = ทำแล้วและผ่านเกณฑ์ (อ้างไฟล์/test); **ต้องแก้** = มีอยู่แต่ต้องเปลี่ยน (อ้างไฟล์ที่ต้องแก้); **ใหม่** = ยังไม่มี. สถานะตรวจจากการอ่านโค้ดจริงบน branch นั้นเมื่อ 2026-10-12. ตาม D5 คำว่า "มีแล้ว" ไม่ได้บังคับให้ใช้โค้ดเดิม.
- **สถานะการตรวจสอบข้อกฎหมาย/ระเบียบ** (§11): **verified** = อ่านจากต้นฉบับแล้ว; **secondary-source** = มาจากสรุปผลการค้นหาของเว็บไซต์ราชการหรือเว็บไซต์ครู (เปิดต้นฉบับไม่ได้เพราะ proxy บล็อกโฮสต์ราชการไทยระหว่างการวิจัย); **unverified** = มาจากความรู้ของโมเดลหรือแหล่งที่ขัดแย้งกัน. **กฎใดที่ยังไม่ verified ต้องทำงานเป็น "คำเตือน" ไม่ใช่ "การบล็อก"** (P6).
- ตัวเลขทุกตัวที่มีคำว่า "target, to be validated" เป็นเป้าหมายตั้งต้น ต้องปรับเมื่อได้ข้อมูลจากการนำร่อง.
- ข้อความ "ระบบต้อง …" ใน FR เขียนให้ทดสอบได้. ถ้าอ่านแล้วไม่รู้ว่าจะทดสอบอย่างไร ให้ถือว่าเป็นข้อบกพร่องของ PRD.

## 1. ปัญหา

### 1.1 ข้อความปัญหา (Problem statement)

ครูและผู้บริหารสถานศึกษาในสังกัด สพฐ. เก็บและจัดเรียง **หลักฐานชิ้นเดิมซ้ำหลายครั้งต่อปี**: ทำเป็นหน้า Google Sites หรือ Canva แยกทีละตัวชี้วัดสำหรับการประเมิน PA แต่ละรอบ, อัปโหลดอีกครั้งเข้าระบบ DPA ซึ่งมีข้อกำหนดรูปแบบไฟล์และวิดีโอเฉพาะ, และใช้อีกครั้งสำหรับการขอรางวัลหรือการประเมินอื่น [digest: market F6, F11]. การจับคู่หลักฐานกับ **15 ตัวชี้วัด** ในระดับการปฏิบัติที่คาดหวังของ **วิทยฐานะ** และประเภทห้องเรียนของแต่ละคนเป็นงานมือ ผิดพลาดง่าย และมักทำใกล้กำหนดส่ง. กรรมการต้องไล่เปิดลิงก์ที่กระจัดกระจาย [digest: market F12]. ผลคือเสียเวลาที่ควรใช้สอน, คำขอ DPA ถูกตีกลับเพราะรูปแบบ ความยาว หรือความครบถ้วน [R-OTEPC-4201; digest: market F11], และไม่มีหลักฐานชิ้นใดถูกนำกลับมาใช้อย่างเป็นระบบ.

**SEIP แก้ปัญหานี้โดย**: ให้บันทึกหลักฐานจากงานจริงได้ครั้งเดียว (จากมือถือ ณ เวลาที่สอน หรือจากเว็บ), ให้ AI ที่ทำงานในประเทศไทยเสนอว่าหลักฐานนั้นสนับสนุนตัวชี้วัดใดบ้างพร้อมเหตุผลและตำแหน่งในไฟล์, ให้ครูเป็นผู้ยืนยัน, แล้วนำหลักฐานที่ยืนยันแล้วไปใช้ซ้ำในทุกตัวชี้วัด ทุกแบบฟอร์ม และชุดเอกสาร DPA โดยไม่ต้องคัดลอกไฟล์.

### 1.2 สิ่งที่ปัญหานี้ **ไม่ใช่**

- **ไม่ใช่การขาดช่องทางยื่นทางการ.** ก.ค.ศ. มีระบบ DPA (Digital Performance Appraisal, `dpa-sso.otepc.go.th`) เป็นช่องทางทางการสำหรับคำขอวิทยฐานะ ซึ่งกรรมการ 3 คนประเมินออนไลน์ [R-OTEPC-5971 — secondary-source] และปัจจุบันมีระบบย่อยบันทึกข้อตกลงในการพัฒนางาน (PA) [R-KRUCR-DPA2569 — secondary-source]. SEIP จึงเป็น **ชั้นทำงานตลอดปีที่อยู่ก่อนหน้า DPA** ไม่ใช่ตัวแทน DPA. ไม่พบ API สาธารณะของ DPA [digest: framework-currency F9].
- **ไม่ใช่การให้ AI เขียน PA แทนครู.** เครื่องมือแบบนั้นมีอยู่แล้วฟรีในรูปชุด prompt สำหรับ chatbot ทั่วไป [R-AI-PROMPTS — secondary-source] และเสี่ยงต่อความซื่อตรงทางวิชาชีพ (§10.3).

### 1.4 สิ่งที่ผู้ใช้ทำกันอยู่ตอนนี้

ครูใช้ Google Sites จัดหน้าแยกตามตัวชี้วัด (template ฟรีหรือราคาประมาณ 88 บาท), งานนำเสนอ Canva เผยแพร่เป็นเว็บ, และแบบฟอร์ม Word PA1–PA5 ที่ส่งต่อกันระหว่างโรงเรียน [R-MARKET-DIY — secondary-source]. หลักฐานถูกคัดลอกหรือแปะลิงก์ด้วยมือทีละตัวชี้วัด ไม่มีกราฟการใช้ซ้ำ. ไม่พบผลิตภัณฑ์ไทยที่ให้ AI จัดหลักฐานที่อัปโหลดเข้ากับตัวชี้วัด PA/DPA แล้วใช้ซ้ำ [digest: market F7]. (การไม่พบคู่แข่งไม่ได้พิสูจน์ว่าไม่มี ต้องสำรวจกลุ่ม LINE/Facebook เพิ่ม: OQ-25.)

## 5. หลักการผลิตภัณฑ์ (Non-negotiables)

หลักการเหล่านี้ขัดกับ FR ใดไม่ได้. ถ้า FR ขัดกับหลักการ ให้ถือหลักการเป็นหลักและแก้ FR.

| ID | หลักการ | ทดสอบได้อย่างไร |
|---|---|---|
| **P1 — อัปโหลดครั้งเดียว** | หลักฐานหนึ่งชิ้นถูกเก็บครั้งเดียวและเชื่อมกับตัวชี้วัด แบบฟอร์ม และชุดเอกสารได้หลายรายการโดยการอ้างอิง ไม่คัดลอกไฟล์. ไฟล์เดียวกันที่อัปโหลดซ้ำต้องถูกรู้จำ | FR-012, FR-045; ตรวจว่าไม่มีไบต์ของหลักฐานซ้ำในชุดส่งออก (ยกเว้นไฟล์ derivative) |
| **P2 — ไม่สร้างงานเอกสารใหม่** | SEIP รับหลักฐานจากงานจริงที่มีอยู่แล้ว (แผนการสอน ภาพ/วิดีโอในชั้นเรียน ผลงานผู้เรียน เกียรติบัตร). ไม่มีช่องกรอกบังคับนอกจากตัวไฟล์ (FR-005). รายงานที่ระบบสร้างเป็น **สรุป** ของหลักฐานที่มีอยู่ ไม่ใช่หลักฐานใหม่ | ไม่มีฟอร์มใดใน v1 ที่บังคับกรอกมากกว่าไฟล์ + การยืนยัน |
| **P3 — AI เสนอ มนุษย์ตัดสิน** | AI สร้างได้เฉพาะ "ข้อเสนอ" (`suggested`). ไม่มีเส้นทางใดเปลี่ยนสถานะเป็น `confirmed` โดยไม่มีการกระทำของมนุษย์ที่ถูกบันทึก. **เฉพาะการจับคู่ที่ยืนยันแล้วเท่านั้นที่ไปถึงผลลัพธ์ทางการ** (มุมมองกรรมการ แบบฟอร์ม ชุด DPA). AI ไม่สร้างหลักฐานหรือข้อความที่นำเสนอเป็นผลงานของครู | FR-029, FR-045; test ที่พยายามยืนยันด้วย AI job ต้องล้มเหลว |
| **P4 — AI ทุกข้อเสนอต้องอธิบายตัวเองได้** | ทุกข้อเสนอมีเหตุผลภาษาไทยสั้น ๆ ที่อ้างถึงข้อความเกณฑ์ และมีตัวชี้ตำแหน่ง (หน้า/บล็อก, ช่วงเวลาในวิดีโอ, บริเวณในภาพ) ที่ตรวจสอบแล้วว่ามีอยู่จริงในเนื้อหาที่สกัดได้ | FR-024, FR-025 |
| **P5 — หลักฐานและ AI ไม่ออกนอกประเทศไทย** | ไฟล์ต้นฉบับ ไฟล์ derivative ข้อความที่สกัด ข้อมูลเข้าและออกของ AI log และ backup อยู่ในประเทศไทย. AI เป็น open model ที่ host เองในไทย (D1) | NFR-Res-01..05, FR-026 |
| **P6 — หลักเกณฑ์เป็นข้อมูลที่มีวันมีผลและมีเวอร์ชัน** | ตัวชี้วัด, ข้อความเกณฑ์ตามวิทยฐานะ, น้ำหนัก, เกณฑ์ผ่าน, กติกากรรมการ, กติกาหลักฐาน (จำนวน ความยาว รูปแบบ) และกติกาคุณสมบัติ เป็นข้อมูลที่มี `effective_from/to`, แหล่งอ้างอิง และสถานะการตรวจสอบ. ไม่ hard-code. **กฎที่ยังไม่ verified ทำงานเป็นคำเตือนเท่านั้น** | FR-080–FR-086 |
| **P7 — Portfolio เป็นของบุคคล** | หลักฐานและการจับคู่ที่ยืนยันแล้วเป็นของครูตลอดอาชีพ โรงเรียนเป็นบริบทของแต่ละวงรอบ. ย้ายโรงเรียนแล้ว portfolio ไปด้วย (D2) ภายใต้กติกาข้อมูลผู้เรียนของ controller | FR-050, FR-051 |
| **P8 — ปิดอย่างปลอดภัยเมื่อไม่แน่ใจ (fail closed)** | หลักการเดียวกับ ADR-0009: ถ้าการสแกนมัลแวร์ไม่สำเร็จ ไฟล์ไม่ถูกเปิดให้ดาวน์โหลดหรือประมวลผล; ถ้าตรวจสอบสิทธิ์ไม่ได้ ปฏิเสธ; ถ้า AI ล้มเหลว หลักฐานยังเก็บไว้และให้จับคู่ด้วยมือได้. "ไม่พร้อม" ไม่เท่ากับ "ปลอดภัย" | FR-020, FR-032, FR-095 |
| **P9 — ไม่มีข้อมูลส่วนบุคคลใน event และการแจ้งเตือน** | Event และ push payload มีแต่ ID และสถานะ. เนื้อหาโหลดหลังยืนยันตัวตน | FR-101; มีอยู่แล้วในหลักการของ `docs/contracts/events.yaml` |
