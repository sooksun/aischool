# ADR-0017: ขอบเขต v1 และกฎการประเมินเป็นข้อมูลที่มีวันมีผล

## Status
**Accepted** (2026-10-12, owner อนุมัติ; เสนอ 2026-10-12) — ดำเนินการใน P0. Amends ADR-0003 ข้อ 3 (กรรมการ 3 คน และ "≥70% ทุกคน" เปลี่ยนจาก schema เป็นข้อมูล)

## Context
- D3: v1 คือ evidence hub. การให้คะแนนของกรรมการเลื่อนไป v2
- `evaluation-framework.md` อ้างเฉพาะคู่มือต้นฉบับ 2564 แต่หลักเกณฑ์ถูกแก้มาหลายฉบับ ได้แก่ ว15/2565, ล679/2566, ล1144/2567, ว18/2567, ล1683/2567, ล1222/2568 และ ว1/2569 (ส่วนใหญ่ยืนยันได้จาก**แหล่งทุติยภูมิ**เท่านั้น)
- เกณฑ์ผ่าน "≥70% จากกรรมการทุกคน" ถูก hard-code ไว้ใน DDL แต่ DPA ใช้ 2 ใน 3 คน
- ว19/2568 เป็นเกณฑ์ของครูผู้ช่วย ไม่ใช่ PA

## Decision
1. **ขอบเขต v1 ประกอบด้วย**:
   - evidence hub
   - มุมมองกรรมการรายตัวชี้วัด (validate/return)
   - DPA Pack ZIP
   - PA2 workbook (XLSX)
   - อัปโหลด PA3 ที่ลงนามแล้ว
2. **โค้ดการให้คะแนนและการอนุมัติรายงาน** ถูก freeze ไว้หลัง `FEATURE_SCORING=false`. ไม่ลงทะเบียน route แต่ test ยังรันใน CI job แยก (frozen)
3. ข้อมูลต่อไปนี้เป็น **ข้อมูลแบบ versioned ที่มี `effective_from` แหล่งอ้างอิง และ flag `verified`**:
   - `framework_amendment` และ `indicator_crosswalk`
   - `programme`
   - `pass_rule`
   - `committee_eligibility_rule`
   - `eligibility_rule`
   - `dpa_slot_profile`
4. **กฎของ ก.ค.ศ. ที่ยัง unverified ทำงานเป็นคำเตือนเท่านั้น**. กฎ PDPA, residency, ความปลอดภัย และข้อห้ามจดจำใบหน้า **บังคับเต็มที่เสมอ**
5. **"verified" หมายถึงอ่านจากต้นฉบับแล้ว และตรวจสายการแก้ไขจนถึงฉบับล่าสุดแล้วด้วย**. กฎที่อ่านจากคู่มือ 2564 เท่านั้นได้สถานะ `verified-original / pending-amendment-check`
6. เกณฑ์ 70% ที่ hard-code **ถูกถอดออกจาก DDL**
7. แถว placeholder ของครูผู้ช่วย (72 แถว) **ไม่ถูกใช้ใน prompt ของ PA**
8. **นอกขอบเขต v1**: ว23/2564 (การประเมินเลื่อนเงินเดือน; สงวนแถว `programme` ไว้) และ ว19/2568

## Consequences
- ต้องมี work order ให้ owner (หรือผู้ที่เข้าถึงเว็บราชการได้) อ่านต้นฉบับ ล1222/2568, ว15/2565 และคู่มือ DPA 2569 ก่อนเปลี่ยน flag ใดเป็น `verified`
- `evaluation-framework.md` ต้องแก้ตาม PRD §11.3 (C-01 ถึง C-09)
